# 2025-07-22

## 上午

​	今天上午主要调研了下ERP问答助手用的知识库的Markdown文档内图片的图床。**图床**是一个专门用于存储和托管图片的在线平台，我打算用对象存储作为基底，但无奈的是Minio因为改了开源协议由Apache License Version 2.0改成了AGPLv3，后者有污染性，只要用了这个协议的软件，就需要把用了这个Minio的项目源码开源才行，有法律风险，所以需要调研一款替代品，其实我一直在关注这个，之前知道有Ceph，但是这玩意实在太重量了，仅仅当个图床实在是大柴小用了，于是我今天在bing上搜到了一款足以替代的方案，这就是接下来说的 RustFS，看名字就知道是用Rust编写的文件系统，现在Rust语言这么火，什么东西都想去沾点儿。但是既然是用Rust编写的，起码性能和内存安全性问题不用去操心。这个看着还是国产的，还是基于Apache License Version 2.0的协议，也就是Minio之前用的，这下是可以用于商业用途了，只要保留logo就可以了。

![image-20250723180738403](https://rustfs.wenyongdalucky.club:443/astro-paper/image-20250723180738403.png)

也支持分布式部署，看这架构，应该是每个节点作用是平级的，这样容易管理，不像k8s那样还有个Control Panel（控制平面）。

![image-20250723180847598](https://rustfs.wenyongdalucky.club:443/astro-paper/image-20250723180847598.png)

然后我就开始研究怎么去部署，可以部署到基本上主流的系统上，Linux、macOS、Windows，以及要用的Docker的这种容器部署方式。

所以我就直奔主题了，如何用Docker部署。首先确认了官方有image，免了还得去编译源码，再利用Dockerfile制作image的麻烦。![image-20250723181054214](https://rustfs.wenyongdalucky.club:443/astro-paper/image-20250723181054214.png)

官方文档还是有很多疏漏的，一会儿配置文件方式去配置，一会儿又通过Docker的Environment去配置，整的云里雾里的，还有这端口号，让从容器里暴漏9000和9001，后者用于web console，结果浏览器上根本就打不开，最后还是通过9000打开的，所以说RustFS已经是把文件服务器和web console合并成一个port了。以下是我编写的`docker-compose.yml`文件

```yaml
services:
  rustfs:
    image: 'rustfs/rustfs:latest'
    container_name: 'rustfs'
    restart: always
    environment:
      - 'TZ:Asia/Shanghai'
      - 'RUSTFS_ACCESS_KEY=rustfsadmin'
      - 'RUSTFS_SECRET_KEY=rustfsadmin'
      - 'RUSTFS_CONSOLE_ENABLE=true'
      - 'RUSTFS_TLS_PATH=/certs'
    ports:
      - '9000:9000'
    volumes:
      - /etc/localtime:/etc/localtime:ro
      - /mnt/rustfs/data:/data
      - /usr/ssl:/certs
    command:
      - "rustfs"
      - "--console-enable"
      - "--server-domains"
      - "rustfs.wenyongdalucky.club"
```

建立好对应的宿主机内挂载目录后，就可以通过`docker compose up -d`进行启动容器了，整体来说还是很方便的。而且还解决了个我之前用Minio一直没解决的问题，就是通过域名加SSL的方式去通过nginx反向代理文件服务器，这一点儿做的很方便，我之前也没细致的研究过，主要是Minio占资源大，动不动就CPU和Memory双双飙升，实在令我抓狂。看了眼Web Console，还是很简洁大方的，个人感觉比Minio好看。

![image-20250723181707674](https://rustfs.wenyongdalucky.club:443/astro-paper/image-20250723181707674.png)

![image-20250723181716550](https://rustfs.wenyongdalucky.club:443/astro-paper/image-20250723181716550.png)

试了下功能都正常，和Minio都是一样的，于是决定用这个了。接着是选本地的客户端，纠结使用Picgo-Core还是新出的PicList，前者只需npm包管理器安装成全局即可，后者功能强大，但是需额外装软件，考虑到给测试用的便捷性，决定还是用了前者。至此调研基本完毕，并将Picgo-Core的安装步骤及在Typora中的配置步骤整理文档到KM上，方便测试去用。

## 下午

​	接着我又继续开始弄ERP的问答助手前端了，React这个词仿佛躲不开了，今天要解决的就是反馈弹窗确定按钮增加loading，拟使用promise异步和resolve事件进行传递，其实最后也没用上resolve，直接在父组件用传递的async事件就行了，然后子组件也就是模态框内增加confirmLoading状态，并改确认事件为异步

![image-20250723182223994](https://rustfs.wenyongdalucky.club:443/astro-paper/image-20250723182223994.png)

还是挺容易解决的。接着就是在取消赞成和反对的按钮增加个消息确认框，免得误点直接就取消了。这块卡了很久，引了Ant Design的Popconfirm气泡确认框控件，但是不是报错就是不触发，最后发现是因为这个问答助手是Dify二次开发的项目内的Tooltip控件导致的，于是果断切换成了Ant Design的Tooltip，问题迎刃而解，看来这个也不能随便搭配
